# Samples

| File | What it is |
|---|---|
| `meshgate_demo.blend` | Source of the "crate with a beacon" demo asset (Blender 3.5+, textures packed). Generated by the `sources/blender/make_demo_scene.py` script. |
| `meshgate_demo.glb` | Canonical GLB per the contract: 17 meshes, 4 PBR materials, 2 textures at 1024², 2 animations (`lid_open`, `beacon_spin`). |
| `meshgate_demo.draco.glb` | The same asset with Draco compression — for testing decoders in runtimes. |
| `meshgate_hero.blend` / `.glb` / `.fbx` | Demo character: a smooth 1.75 m mannequin (voxel remesh), a 21-bone skeleton with Unity Humanoid names, weights, UV unwrap, 3 materials, `idle` and `wave` bone animations. Generated by `sources/blender/make_demo_character.py`. The FBX imports into Unity as a Humanoid avatar. |
| `meshgate_lantern.*` | Lantern: glass with `KHR_materials_transmission`/`ior`, flame emission, a chain; animations `swing` (swinging around the suspension point) and `flicker` (flame scale). |
| `meshgate_barrel.*` | Barrel: procedural albedo, normal (from a height map) and roughness maps, cylindrical unwrap, no animations. |
| `meshgate_drone.*` | Drone: a deep hierarchy (body → arms → motors → rotors → blades), `hover` and `rotors` clips (one clip across 4 objects), 90 KB. |
| `packs/zombie_cats/` | Example pack **Zombie Cats**: 11 stylized assets + a diorama, one palette material, collision variants, a Humanoid zombie cat — see [its README](packs/zombie_cats/README.md). |
| `packs/generated/` | Example pack **Generated**: six assets made by `meshgate.py gen` — kit code from text and from a picture, and a TripoSR mesh from a picture — each with four quality tiers. See [its README](packs/generated/README.md). |
| `index.json` | List of samples for the web viewer gallery. |
| `meshgate_demo.fbx` | Fallback path for the Unity/Unreal editors: meters, Y-up, 2 takes, textures embedded. Produced by the same export with the `--fbx` flag; validation — `core/validate_fbx.py`. |

The asset is deliberately built like a "real" game prop: a hierarchy (`meshgate_demo → crate_body → crate_lid → beacon_post → beacon_ring`), origin at the base, the lid rotates around its hinge, the beacon is a child of the lid and moves with it, and there is emission (`KHR_materials_emissive_strength`) and transparent glass. This catches typical adapter bugs: lost hierarchy, wrong axes, animations on child nodes, transparency.

## Rebuild

```bash
BLENDER=/Applications/Blender.app/Contents/MacOS/Blender   # macOS; on Linux usually just `blender`
$BLENDER -b -P sources/blender/make_demo_scene.py -- --blend samples/meshgate_demo.blend
$BLENDER -b samples/meshgate_demo.blend -P sources/blender/export_meshgate.py -- --out samples/meshgate_demo.glb --fbx --validate   # + meshgate_demo.fbx
$BLENDER -b -P sources/blender/make_demo_character.py -- --blend samples/meshgate_hero.blend
$BLENDER -b -P sources/blender/make_demo_props.py -- --out-dir samples                       # lantern, barrel, drone
for n in hero lantern barrel drone; do $BLENDER -b samples/meshgate_$n.blend -P sources/blender/export_meshgate.py -- --out samples/meshgate_$n.glb --fbx --validate; done
$BLENDER -b samples/meshgate_demo.blend -P sources/blender/export_meshgate.py -- --out samples/meshgate_demo.draco.glb --draco --validate
```

## Your own character (realistic avatar, Mixamo, Rigify, UE Mannequin)

```bash
$BLENDER -b -P sources/blender/animate_humanoid.py -- --in ~/Downloads/avatar.glb --blend samples/_local/avatar.blend
$BLENDER -b samples/_local/avatar.blend -P sources/blender/export_meshgate.py -- --out samples/_local/avatar.glb --fbx --validate
```

`animate_humanoid.py` finds Humanoid bones by name (Unity / Mixamo / Rigify / UE), converts to meters with the origin at the feet, and adds `idle` and `wave` if there are no animations of its own. The `samples/_local/` folder is ignored by git — for third-party assets with unclear licensing.

Your own `.glb`/`.blend` files in this folder are ignored by git — put them here for local checks without the risk of bloating the repository.
