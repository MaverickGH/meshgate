# Генерация: текст или картинка → готовый для игры ассет

`meshgate.py gen` превращает описание, картинку или и то и другое в проверенный ассет, по файлу на каждый уровень
качества. [MeshGate Studio](../apps/studio/README.ru.md) делает то же самое в окне.

Движков два. Оба приходят к одному результату: файлам, которые проходят контракт ассета и бюджет каждого уровня.

| Движок | Как получается форма | Лучше всего для |
|---|---|---|
| **kit** | ИИ-инструмент командной строки (Claude Code, Codex, Gemini, Ollama, свой) пишет короткую функцию `build(mg)` на наборе для моделирования MeshGate. Картинка, если она есть, служит образцом. | Твердотельные и стилизованные предметы: чистые формы, один материал, редактируемый код |
| **mesh** | Нейросеть делает сетку по картинке или тексту: TripoSR на твоей машине или Meshy, Tripo, TRELLIS, Hunyuan3D в облаке. MeshGate доводит её под каждый уровень. | Фото настоящих предметов, органические формы, всё, что набор не описывает |

С `--engine auto` (по умолчанию) картинка идёт в движок mesh, если готов генератор, а описание — в движок kit.

```bash
python3 meshgate.py gen --list-ai                                    # ИИ-CLI, генераторы сеток, Blender
python3 meshgate.py gen "a cast-iron fire hydrant" --size 0.8        # текст → код набора (по умолчанию Claude Code)
python3 meshgate.py gen --setup triposr                              # один раз: локальная картинка → 3D (MIT, ~3 ГБ)
python3 meshgate.py gen --image photo.jpg --size 0.8                 # картинка → TripoSR → доводка
python3 meshgate.py gen --image photo.jpg --engine kit               # картинка → код набора, ИИ смотрит на неё
python3 meshgate.py gen "ржавый робот" --engine mesh --provider meshy   # текст → облачная сетка (MESHY_API_KEY)
python3 meshgate.py gen --mesh downloaded.glb --size 1.5             # любая сетка → контракт, без генерации
python3 meshgate.py gen --mesh crates.fbx --split                    # …каждая отдельная вещь своим объектом, чтобы двигать в движке
python3 meshgate.py send out/gen/crates --to unity --project ~/Games/MyGame   # в проект Unity / Godot / Unreal или в Blender
python3 meshgate.py gen --code my_model.py --name my_model           # свой build(mg), без ИИ
```

Результат складывается в `out/gen/<имя>/`:

| Файл | Что это |
|---|---|
| `<имя>.glb` | Канонический ассет, собранный на самом богатом из запрошенных уровней |
| `<имя>.<уровень>.glb` | Та же модель с детализацией каждого более лёгкого уровня |
| `<имя>.fbx`, `.unreal.fbx`, `.godot.glb` | Варианты для движков, как у аддона |
| `<имя>.blend`, `<имя>.png` | Сцена Blender и превью |
| `<имя>.py` | Движок kit: код, который построил модель — перезапустить, поправить, закоммитить |
| `input.png`, `raw_<генератор>.glb` | Движок mesh: твоя картинка и нетронутый ответ генератора |
| `gen.json`, `<имя>.report.json` | Сводка для Studio и CI: треугольники, бюджеты, клипы, проблемы |

## Движок kit: код пишет ИИ

![текст → код → Blender по уровням → проверенные файлы](img/generation-flow.svg)

1. **Промпт.** MeshGate заполняет [`sources/generate/prompts/model.md`](../sources/generate/prompts/model.md):
   описание, стиль, уровни качества из [`core/profiles.json`](../core/profiles.json) и API набора для моделирования.
   API читается из докстрингов набора, поэтому промпт не может разойтись с кодом. С картинкой в промпт добавляется
   раздел: повторить её силуэт, детали и цвета.
2. **Код, а не меши.** ИИ отвечает одной функцией `build(mg)` поверх набора
   [`meshgate_blender/modeling.py`](../sources/blender/meshgate_blender/modeling.py): примитивы, тела вращения, трубы,
   выдавливание, зеркало, объединение, шарниры, анимация. Код короткий, читаемый, его видно в диффе, и тот же ИИ
   может его исправить.
3. **Ограждения.** [`safety.py`](../sources/generate/safety.py) отклоняет код, который импортирует что-то кроме
   `math`, `random` и `mathutils`, трогает `bpy`, файлы, процессы или имена с `_`. Раннер выполняет код с урезанными
   встроенными функциями в `blender -b --factory-startup --disable-autoexec` и с таймаутом. Это сужает, куда может
   дотянуться запутавшаяся или атакованная через промпт модель. Это не песочница, поэтому код от моделей, которым
   не доверяешь, стоит просмотреть.
4. **Сборка под каждый уровень.** [`run_generated.py`](../sources/generate/run_generated.py) запускает `build(mg)` по
   разу на уровень, с `mg.tier`. Круглые формы получают больше сегментов на богатых уровнях, мелкие детали код включает
   через `mg.at_least("mobile-high")`. Это «детализация по необходимости»: телефон получает лёгкую модель, а не
   упрощённую тяжёлую.
5. **Контракт бесплатно.** Все детали попадают в один материал-палитру. Его текстуры цвета, шероховатости,
   металличности и свечения держат по клетке 32 пикселя на цвет, поэтому весь ассет — один материал и один draw call
   на любом уровне. Грани, спрятанные внутри другой замкнутой детали того же меша, удаляются: рука, утопленная в
   тело, основания колючек внутри ствола, верх горшка под землёй. Грани, которые пересекают поверхность другой детали,
   остаются, поэтому дыр не видно; на кактусе из студии это сняло 15–20 % треугольников на каждом уровне.
6. **Цикл исправлений.** Если сборка падает, выходит за бюджет уровня, не проходит валидатор или получается не того
   размера, проблемы уходят обратно ИИ вместе с его прошлым кодом, до `--attempts` раз (по умолчанию 3).

**Сначала нарисовать, потом строить (`--concept sheet`).** ИИ, который видит предмет, моделирует его намного лучше,
чем тот, кто читает одну фразу. С `--concept sheet` MeshGate сначала просит модель картинок нарисовать ортографический
лист видов по описанию: спереди, сбоку, сзади и сверху на одном квадрате, в одном масштабе, при ровном свете на ровном
фоне. Промпт лежит в [`prompts/concept_sheet.md`](../sources/generate/prompts/concept_sheet.md). Лист уходит ИИ движка kit
как образец вместе с правилами чтения: какой вид даёт ширину, глубину и план и куда в каждом смотрит перёд. Если Codex
CLI вошёл через ChatGPT, один инструмент делает оба шага: gpt-image-2 рисует лист, а Codex пишет код, без ключа API.
`--concept single` рисует вместо листа один ракурс три четверти — по нему восстанавливают 3D генераторы вроде TripoSR.

```bash
python3 meshgate.py gen "Уличный фонарь с фонарём в форме рыбы" --concept sheet --ai codex --image-provider codex --size 3.2
```

Проверка промптов: фонарь-рыбу из пака котов-зомби отрендерили листом видов, как промпт концепта просит нарисовать
gpt-image-2, и отдельно одной картинкой три четверти. Два прогона ИИ получили одно и то же описание и по одной картинке.
Прогон по листу точнее передал конструкцию: кронштейн, идущий вверх, и ржавую полосу на 40 % высоты. Прогон по одной
картинке сделал кронштейн горизонтальным с лишним подкосом и опустил полосу. Настоящую высоту по картинке не узнать ни
тому, ни другому, поэтому передавай `--size`, когда она важна.

![Лист видов](img/concept-sheet-example.png)
![Оригинал, по листу, по одной картинке](img/concept-sheet-vs-single.png)

**Картинки для движка kit.** Картинка копируется в пустую рабочую папку ИИ-CLI как `reference.png`. Claude Code
получает инструмент Read только для этого и больше ничего; Codex получает `-i`; Gemini — `@reference.png`; Ollama —
путь, который читают модели со зрением вроде `llava`; своя команда — `{image}`.

## Движок mesh: картинка → 3D и текст → 3D

| `--provider` | Где работает | Принимает | Нужно | Лицензия |
|---|---|---|---|---|
| `triposr` | Твоя машина: Apple GPU (MPS), CUDA или CPU | картинку | `meshgate.py gen --setup triposr` | MIT, код и веса |
| `meshy` | Облако [Meshy](https://docs.meshy.ai) | картинку или текст | `MESHY_API_KEY` | по условиям Meshy |
| `tripo` | Облако [Tripo](https://platform.tripo3d.ai) | картинку или текст | `TRIPO_API_KEY` | по условиям Tripo |
| `fal` | [fal.ai](https://fal.ai): TRELLIS, Hunyuan3D 2, TripoSR | картинку; текст через FLUX → картинку | `FAL_KEY` | TRELLIS и TripoSR MIT; Hunyuan3D не для ЕС, Великобритании и Южной Кореи |
| `command` | Всё, что запускаешь сам: `--mesh-cmd "gen {image} --out {out}"` | картинку или текст | — | твоя |

**Текст → 3D в движке mesh.** Meshy и Tripo принимают текст напрямую. Для генераторов, которым нужна картинка,
MeshGate сначала рисует образец: один предмет, целиком, по центру, на ровном фоне, при ровном свете. Рисует gpt-image-2
через Codex (вход через ChatGPT), OpenAI `gpt-image-1` (`OPENAI_API_KEY`) или FLUX schnell на fal (`FAL_KEY`), выбор через
`--image-provider`. Без ключей
текст идёт в движок kit, которому картинка не нужна.

**Доводка: что происходит со сгенерированной сеткой.** [`refine.py`](../sources/generate/refine.py) работает в
Blender для любого генератора и для файлов из `--mesh`. Её шаги:

1. **Нормализация.** Импортирует GLB, glTF, OBJ, FBX, PLY или STL, применяет трансформации, убирает риги и сливает всё
   в один исходник. Масштабирует его до `--size` в метрах, центрирует и ставит на землю.
2. **Выпрямление.** Генераторы по одной картинке считают камеру горизонтальной, поэтому фото сверху даёт наклонённую
   модель. MeshGate ищет наклон с самым широким плоским основанием, как предмет стоит на полу, и сообщает поправку.
   `--no-upright` выключает это, `--turn` поворачивает перёд.
3. **Чистка.** Сливает дубли вершин, удаляет висящую геометрию и летающие крошки, разворачивает нормали наружу.
4. **По уровням.** Копия упрощается до доли бюджета треугольников уровня: половины на mobile-low и четверти на PC,
   с множителем `--detail`. Копия получает новую UV-развёртку.
5. **Запекание.** Cycles запекает цвет и, начиная с mobile-mid, карту нормалей в касательном пространстве с плотного
   исходника на лёгкую копию. Размеры текстур подобраны под бюджет памяти каждого уровня с учётом мип-мапов: 512 px на
   mobile-low и до 2048 + 2048 px на PC. Цвет вершин, текстуры и простые цвета материала запекаются одинаково.
6. **Экспорт.** Собирает один PBR-материал и экспортирует каждый уровень экспортёром MeshGate. Самый богатый уровень
   становится каноническим файлом с вариантами для движков и `--collision` по желанию.

Цвета TripoSR выходят темнее картинки и записаны как значения картинки. MeshGate декодирует их и подгоняет средний цвет
под объект на фото.

## Параметры

| Параметр | По умолчанию | Смысл |
|---|---|---|
| `--image` | — | Картинка: картинка → 3D или образец для кода набора |
| `--engine` | `auto` | `kit`, `mesh` или `auto` |
| `--provider` | первый готовый | `triposr`, `meshy`, `tripo`, `fal`, `command` |
| `--fal-model` | `fal-ai/trellis` | или `fal-ai/hunyuan3d/v2`, `fal-ai/triposr` |
| `--image-provider` | первый готовый | Кто рисует картинки по тексту: `codex` (вход через ChatGPT, без ключа), `openai` или `fal` |
| `--concept` | `none` | `sheet`: сначала нарисовать лист видов спереди/сбоку/сзади/сверху и строить по нему; `single`: один ракурс 3/4 |
| `--mesh` | — | Довести готовый файл сетки вместо генерации. Studio: перетащи модель (GLB, FBX, OBJ, PLY, STL) туда же, куда картинку — она сохранится в `_inputs/models` библиотеки и соберётся как сгенерированная |
| `--split` | выкл | Каждая отдельная вещь — свой объект под общим корнем: из кучи ящиков получится объект на каждый ящик, с именем по цвету и точкой опоры внизу, чтобы двигать, менять и переделывать их по отдельности в Unity, Godot, Unreal или Blender. Мелочи, касающиеся большой детали (гвоздь, наклейка), остаются с ней. Kit и `--mesh`. Studio: **Разделить на части** |
| `--edits` | — | Вместе с `--split`: JSON-файл ручных правок частей по имени — `{"crate_2": {"move": [0, 0, 0.4], "turn": 30, "scale": 1.2, "colour": "red"}, "nail_1": {"delete": true}}` (метры, Z вверх; поворот и масштаб вокруг основания части). Хранится как `edits.json` рядом с моделью и применяется при каждой пересборке. Studio: вкладка **«Части»** |
| `--library` | — | Бесплатная модель CC0 / CC-BY с Sketchfab по id: скачивается с указанием автора и доводится, как `--mesh` |
| `--detail` / `--turn` / `--no-upright` | `1` / `0` / выкл. | Движок mesh: множитель доли треугольников, поворот переда, оставить наклон |
| `--vertex-srgb` | авто | Движок mesh: цвет вершин записан как значения картинки (авто для TripoSR и файлов trimesh) |
| `--ai` | `claude` | Движок kit: `claude`, `codex`, `gemini` или `ollama` |
| `--model` | по умолчанию CLI | Имя модели для CLI |
| `--ai-cmd` | — | Любой другой CLI; `{prompt_file}` и `{image}` подставляются |
| `--style` | `stylized` | `stylized`, `lowpoly`, `realistic`, `toon` или своими словами |
| `--size` | по ситуации | Самый большой размер в метрах |
| `--tiers` | все четыре | Уровни для сборки; самый богатый становится каноническим файлом |
| `--tris` | по уровням | Свои лимиты треугольников: `800` на все уровни или `low=150,mid=400,high=900,pc=2000` |
| `--colors` | `texture` | `vertex` кладёт цвета в вершины: совсем без текстур, 1–3 материала |
| `--anim` | — | Kit: какие клипы сделать, `open: крышка открывается; idle: фонарь качается` (или по строке на клип). Подвижные части становятся отдельными мешами с осью; недостающий клип уходит ИИ как проблема. В студии — **«Анимации»** |
| `--texture` | `auto` | Размер запекаемых текстур для файла PC: `1k`, `2k`, `4k`, `8k`. Уровни для телефонов держат свои лимиты; `8k` ещё пишет `<имя>.master.glb` |
| `--pbr` | выкл. | Kit: запечь полный набор PBR (цвет, затенение-шероховатость-металличность, нормали, свечение) для любого стиля, не только realistic |
| `--topology` | `tri` | `quad`: FBX и .blend сохраняют квады; движок mesh перестраивает сетку в квады на каждом уровне. GLB всегда из треугольников |
| `--views` | — | Картинка — лист персонажа: его виды слева направо (`front,3/4front,left,back,right,3/4back`). Лист режется на фигуры, модель сравнивается с каждой под её углом (совпадение контура по видам, полоса наложений `<sheet>.views.png`), ревью называет полосы, где есть разница, а `--fit` берёт ширину по видам спереди и сзади, глубину — по видам сбоку |
| `--fit` | `auto` | Kit с картинкой-референсом: сравнить контуры и цвета, подогнать ширину модели в каждой полосе по высоте (вершины и скелет вместе, не больше ±20 % на полосу) и каждый цвет палитры — по тому, насколько он светлее или темнее остальных на картинке (без её общего освещения, оттенок на треть пути; область, где картинка показывает другой цвет модели, не трогается) — и оставить, если стало ближе; `auto` — всегда, когда есть картинка |
| `--outline` | `auto` | Kit: тун-обводка по силуэту (вывернутая оболочка, уровни mobile-high и PC); `auto` — включена в стиле toon |
| `--pose` | `none` | Kit: поза покоя персонажа со скелетом — `none` (как смоделирован), `a` (A-Pose, руки на 45° вниз), `t` (T-Pose, руки прямо в стороны) |
| `--finish` | `auto` | Kit: `faceted` (плоское затенение, мало сегментов), `weathered` (запечённая грязь, разброс цвета, рельеф), `none`; `auto` берёт по стилю |
| `--targets` | все движки | Варианты канонического файла для движков |
| `--collision` | `none` | `box` или `convex` (Unreal `UCX_`, Godot `-convcolonly`) |
| `--attempts` | `3` | Движок kit: раунды «сборка — отзыв — исправление» |
| `--events` | выкл. | JSON-строки в stdout, их читает Studio |

## Стили, которые выглядят по-разному

Стиль — не только слова в промпте: движок kit закрепляет вид после сборки.

- **`lowpoly` → `faceted`.** Плоское затенение везде, меньше сегментов у круглых форм, без подразделения, фаски в одну
  ступень. Код ИИ не может случайно сгладить модель, а сама она в разы легче: токсичная банка — с 16 до 4 тысяч
  треугольников на уровне PC.
- **`realistic` → `weathered`.** Плоские цвета палитры запекаются в настоящие текстуры с тем, чего им не хватает:
  грязью в углублениях и у земли (ambient occlusion и высота), разбросом цвета по поверхности и мелким рельефом в
  карте нормалей. Размеры текстур следуют бюджету уровня (PC — 2048 px с картой нормалей, mobile-low — 512 px без
  неё). Весь ассет остаётся одним материалом. ИИ говорят давать деталям чистый базовый цвет, а грязь оставить запеканию.
- **Материалы.** Запекание знает, из чего сделан каждый цвет, и рисует это в настоящих метрах: волокна дерева,
  гофрокартон, камень с тонкими трещинами и мхом на верхних гранях и в углублениях, шлифованный металл с пятнами
  ржавчины, сплошную ржавчину, тканое полотно и верёвку, комковатую землю, пористую кость. Материал берётся из имени
  цвета (`wood_dark`, `cardboard_b`, `iron`, `moss_stone`…) или `mg.color(…, material="stone")`; ИИ просят так и
  называть цвета.
- **`stylized`, `toon`** сохраняют чистые цвета палитры и гладкое затенение.

## Качество текстур, полный PBR и топология

- **Размер текстур** (`--texture 1k|2k|4k|8k`, в студии — «Размер текстур») задаёт запекаемые текстуры файла PC. Каждый
  уровень для телефонов держит свой лимит (mobile-low 512 px, mobile-mid 1024, mobile-high 2048), так что один прогон
  по-прежнему обслуживает все устройства. Выше лимита PC (4096) `8k` запекает ещё одну копию PC в `<имя>.master.glb`
  для рендера и кино; она не привязана к уровню. Большое запекание на процессоре идёт минуты — MeshGate даёт ему время.
- **Полный PBR** (`--pbr`, в студии — «Полный набор PBR-карт»): базовый цвет, затенение-шероховатость-металличность
  (ORM glTF, ambient occlusion — в слоте occlusion glTF), карта нормалей и свечение. Реалистичные модели получают его
  всегда; `--pbr` запекает его и для stylized, toon и low-poly — с их точными цветами и без износа. Карты
  шероховатости и свечения держатся до 1024 px, чтобы карта нормалей сохраняла детали в пределах памяти уровня.
- **Топология** (`--topology tri|quad`, в студии — «Топология»). `quad` — для редакторов и дальнейшего моделирования:
  kit объединяет свои треугольники в квады (около 90 %), движок mesh перестраивает каждый уровень в сетку из одних
  квадов — QuadriFlow, если он принимает сетку, иначе воксельный ремеш под бюджет треугольников уровня, а детали
  исходника возвращаются через карту нормалей. FBX и `.blend` сохраняют квады; `tri` триангулирует FBX для движков.
  **GLB всегда из треугольников**: glTF иного не хранит, и любой движок всё равно триангулирует при импорте.
- **Поза** (`--pose none|a|t`, в студии — «Поза персонажа»). Поза покоя, в которой выгружается персонаж со скелетом
  (`mg.rig`). `none` оставляет его как смоделирован — руки свободно вдоль тела; `a` поднимает прямые руки на 45° ниже
  горизонтали (A-Pose), `t` — прямо в стороны (T-Pose): это bind-позы, которых ждут ретаргетинг и настройки Unity
  Humanoid / Mixamo. Kit сам ставит скелет в позу, деформирует в неё сетку и делает её позой покоя, поэтому ИИ всегда
  моделирует руки опущенными; клипы (`idle`, `zombie_walk`, …) играются как задуманы — от опущенных рук.

## Скульптинг: органика, как у художника

Из примитивов выходит хорошая мебель и техника, но деревянные звери. Для существ, растений, камней и еды kit лепит,
как художник в Blender, а промпт подсказывает ИИ, когда это нужно:

| Инструмент | Что делает | Для чего |
|---|---|---|
| `mg.blob(shapes, colour)` | Шары, капсулы и эллипсоиды сливаются в одну гладкую поверхность (метаболы); `"cut": True` вырезает | тела, головы, лапы, морды, подушки, облака |
| `mg.skin(points, radii, colour)` | Гладкое тело вокруг скелета из точек, с ветвлениями | лапы, хвосты, щупальца, корни, ветки |
| `mg.cut(target, cutter)` | Булево вычитание | глазницы, след лапы в камне, окна |
| `mg.bend` / `mg.twist` | Изгиб от основания и скрутка вдоль длины (кольца добавляются сами) | хвосты, уши, рога, верёвки |
| `mg.sculpt(obj, brush)` | Кисти: `grab`, `inflate`, `crease` / `ridge` / `pinch` по линии, `flatten`, `layer`, `noise`, `smooth`; точки прилипают к поверхности | морды, веки, брови, губы, пальцы, гребни черепа, пластины |

| `mg.param(name, default, lo, hi)` | Число, которое художник крутит ползунком в Studio (Доработка → Параметры) без нового запроса к ИИ | размер ушей, длина шерсти, вытянутость рук, число досок |
| `mg.fur(surface, length=, count=)` | Карточки шерсти с вырезом по альфе, в цвет раскрашенной поверхности; на телефонах меньше, на mobile-low нет | шерсть, гривы, пучки, трава |

| `mg.curve(points, radius, colour)` | Гладкая трубка-сплайн через точки, сужение `radii=`, петли `closed=` | провода, лозы, рёбра, позвоночники, пружины, рога |
| `mg.scatter(surface, piece, count)` | Копии детали по поверхности: стоят на ней, повёрнуты и отмасштабированы случайно | камешки, трава, мох, шипы, заклёпки |

| `mg.instance(piece, at, turn=)` · `mg.scatter(..., instances=True)` | Копии с общим мешем: файл хранит его один раз, движки рисуют копии вместе | леса, заборы, фонари вдоль улицы, ящики на складе |
| `mg.modify(obj, kind)` | Модификаторы Blender: solidify, array, displace, smooth, remesh, bevel, wireframe, subdivide, decimate, shrinkwrap | плавники, ряды позвонков, рельеф, клетки, ремни |
| `mg.eye(center, radius, iris)` | Глянцевое глазное яблоко с кольцами радужки и утопленным зрачком — щель, полоса или круг; смотрит, куда скажете | персонажи и существа |

| `mg.cast(obj, "cube", 0.5)` / `mg.symmetrize(obj)` | Подтянуть деталь к чистому бруску, шару или столбу (делает глиняный комок бруском); сделать её строго зеркальной относительно x = 0 | головы и туловища, которые должны читаться блоками; морды после шума скульпта |

| `mg.model(uid, colour, size=)` | Бесплатная модель из библиотеки как деталь для переделки; коробки `keep=` / `drop=` берут только часть | голова, лапа, целая основа, чтобы перекрасить и перелепить |

Цвета с именами fur, pelt или wool в реалистичной отделке получают вид шерсти (тонкие пряди и пучки в цвете и
карте нормалей). ИИ также получает короткие рецепты художника для своего типа объекта — существа, растения, камни,
предметы, здания, переделка модели из библиотеки — они подбираются по описанию (на английском или русском) вместе с
подходящим примером: для существ это [реалистичный зомби-кот](../sources/generate/examples/zombie_cats/realistic/zombie_cat.py).

Каждая модель ещё и измеряется, и факты уходят ИИ вместе с рендерами: детали, висящие отдельно от всего, что стоит на
земле (по номеру строки кода, которая их сделала), какие строки тратят треугольники, размер и асимметрия, а для
запечённых отделок — сколько текстуры занимают UV и насколько ровна плотность текселей. Персонажам перед привязкой
уплотняется сетка у суставов, чтобы локти и колени сгибались, а не сминались. Взвешенные нормали доводят каждую
гладкую модель (плоские грани плоские, фаски берут кривизну), а запечённые UV расслабляются, выравниваются и плотно
упаковываются. Грани одной детали, лежащие ровно на гранях другой (шапочка вровень со столбом, пластина на ящике),
раздвигаются на долю миллиметра, чтобы в движках они не мерцали, а `mg.paint` в стилях с плоским цветом сначала
дробит сетку вдоль края области, поэтому пятно выходит круглым, а не по граням.

«Глина» доводится так, как художник доводит скульптуру: строится на мелкой сетке, сглаживается с сохранением объёма
(без ступенек и наплывов в местах слияния), затем ретопологией (QuadriFlow) превращается в ровные квадраты под плотность
уровня. Low-poly сохраняет грани.

Плотность сетки, как и всё остальное, зависит от уровня. Дальше реалистичная отделка работает как художник по текстурам:

- **Hero-модель для запекания.** PC-сборка уплотняется (примерно до миллиона треугольников), и в неё вдавливается рельеф
  каждого материала — пряди и пучки шерсти, поры кости, бугры и трещины камня, волокна дерева, плетение. Все уровни,
  включая PC, запекают с неё карту нормалей, и лёгкая сетка показывает вылепленные детали. С `--pbr` лёгкие уровни
  запекают с PC-модели.
- **Потёртости по кривизне.** Края находятся семплированием фаски и различаются по выпуклости: гребни светлеют и
  стираются (кость, камень, дерево, металл), во впадинах собирается тёплая тёмная грязь (корни шерсти, щели) — для
  каждого материала по-своему.

## Визуальное ревью: ИИ смотрит на свою модель

`--review N` (Studio: *Круги ревью ИИ*) добавляет после чистой сборки цикл «посмотри и поправь», как художник
проверяет вьюпорт. MeshGate рендерит модель с четырёх сторон (плоские — сверху) и ставит лист рядом с картинкой-образцом
в одно изображение. ИИ получает его вместе со своим кодом, называет главные расхождения — силуэт, пропорции, цвета,
недостающие или висящие в воздухе части — ставит оценку (`MATCH: n/10`) и присылает улучшенный код. Он собирается в
отдельной папке и заменяет модель, только если собрался чисто, поэтому круг не может сделать результат хуже чистой
сборки. Цикл останавливается на 9/10 или после N кругов. ИИ может попросить свою камеру — строка
`VIEW: at=(x, y, z) from=(dx, dy, dz) size=0.3` возвращается в следующем круге крупным планом рядом с четырьмя видами —
и получает вместе с картинкой измеренные факты (висящие детали, треугольники по строкам кода). Каждая собранная версия
хранит оценку своего ревью; если следующий круг оценён ниже, остаётся лучшая версия.

С картинкой-образцом лист ещё и сравнивает их напрямую: MeshGate вырезает контур картинки из фона (без теней), рендерит
силуэт модели с разных ракурсов по кругу и выбирает самый похожий. Картинка и модель с этого ракурса стоят рядом, а под
ними два контура наложены друг на друга — белое, где они совпадают, красное, где форма есть только на картинке, синее —
только у модели. ИИ получает совпадение силуэта числом (1.0 — тот же контур) и указание сначала уменьшать красные и синие
зоны; `gen.json` хранит его для каждого круга.

Каждая чистая сборка, которую написал ИИ, запоминается на твоём компьютере (`~/.meshgate/examples`), и следующий запрос
на что-то похожее получает одну-две ближайшие как готовые примеры — библиотека удачных решений растёт с работой. Лист и ответ каждого круга остаются в папке результата
(`review_1.png`, `review_1.answer.md`, итоговый `views.png`), а `gen.json` хранит оценки и замечания. Тот же рендер
работает и сам по себе: `blender -b -P sources/generate/render_views.py -- model.glb sheet.png 1024 48 reference.png`.

## Библиотека бесплатных моделей

Иногда лучше начать с модели, которую кто-то уже сделал. `meshgate.py library` ищет бесплатные модели на Sketchfab и
скачивает их вместе с указанием автора; `gen --library` доводит модель, как любой файл `--mesh`:

```bash
python3 meshgate.py library search "tree stump" --max-faces 200000
python3 meshgate.py gen --library 7a0f2d413b5846f591b40580f783c53c --size 0.6 --style realistic
```

- **Только лицензии, которые можно менять и использовать в коммерческой игре:** CC0 (автора можно не указывать) и
  CC-BY (указать автора). CC-BY-SA — если добавить `--license by-sa`; тогда и изменённая модель будет CC-BY-SA.
  NonCommercial, NoDerivs, Editorial и лицензии магазина отклоняются, а лицензия проверяется ещё раз перед каждой загрузкой.
- **Авторство идёт вместе с ассетом:** `credit.json` рядом с загрузкой, `credit` в `gen.json` и `CREDITS.txt` рядом
  с готовыми файлами — строка, которую требует CC-BY (название, автор, ссылка, лицензия, «изменено»).
- **Откуда качается:** из зеркала [Objaverse](https://huggingface.co/datasets/allenai/objaverse) на Hugging Face
  (около 800 000 моделей Sketchfab, без аккаунта; индекс 20 МБ скачивается один раз), если модель там есть. Новые модели —
  с Sketchfab по вашему API-токену (`SKETCHFAB_API_TOKEN`, Studio → Ключи; sketchfab.com → Settings → Password & API).
- `library search cat --category` ищет по размеченным вручную категориям Objaverse (их 1156: cat, skull, pumpkin…):
  любая находка скачивается бесплатно из зеркала. `--free` оставляет в текстовом поиске только модели из зеркала.
- Переделка вместо повторного использования: `mg.model(uid, …)` вставляет модель из библиотеки в код kit как деталь,
  чтобы перекрасить, перелепить, подрезать и дополнить, или `keep=` берёт только её голову. Автор тоже попадает в результат.
- Загрузки лежат в `~/.meshgate/library`, не в репозитории. Проверяйте модель сами перед выпуском: лицензия надёжна
  ровно настолько, насколько у загрузившего было право её дать.

## Свои лимиты треугольников и цвет в вершинах

**Лимиты.** Бюджеты уровней — это потолки. Для фонового предмета, мобильной игры или стилизации можно попросить
намного меньше через `--tris` или поле с числом у каждого уровня в студии. Движок kit показывает лимиты ИИ, и тот
строит в их пределах. Всё, что всё равно выше лимита, упрощается до него, а отчёт советует строить меньше. Движок mesh
упрощает сразу до лимита: гидрант из TripoSR на 300 треугольников всё ещё узнаётся.

**Цвет в вершинах.** `--colors vertex` хранит каждый цвет в вершинах (glTF `COLOR_0`), а не в текстурах. У файла ноль
памяти под текстуры и по материалу на группу: обычная, металл и каждый светящийся цвет. На уровнях, где материалов
разрешено меньше, мелкие группы вливаются в основную. Шероховатость усредняется по группе: в glTF нет шероховатости по
вершинам. Движок kit пишет цвета палитры напрямую. Движок mesh запекает цвет плотного исходника в вершины лёгкой копии,
поэтому детализация цвета следует плотности вершин: отлично для low-poly, мягче текстуры на высокой детализации.

| Цель | Цвет в вершинах |
|---|---|
| Web (Three.js) | Показывается: GLTFLoader включает цвет вершин |
| Unity (glTFast) | Показывается: шейдеры glTFast умножают на цвет вершин |
| Godot | Показывается с аддоном MeshGate, он включает цвет вершин; обычная загрузка `GLTFDocument` его не включает |
| Unreal | Импортируется с мешем, в материале ещё не проверен — для Unreal пока используй текстуры |

## Живой Blender для ИИ-клиента (MCP)

`meshgate.py mcp` — это [MCP](https://modelcontextprotocol.io)-сервер: ИИ-клиент собирает код kit в Blender, смотрит на
результат и исправляет его по кругу, а не пишет всю модель вслепую.

```bash
claude mcp add meshgate -- python3 /path/to/meshgate.py mcp
```

(Codex, Cursor и другие MCP-клиенты принимают ту же команду.) Инструменты:

| Инструмент | Что делает |
|---|---|
| `kit_reference` | Правила, все функции `mg.*` с описанием и рецепты художника (`recipe=creature`, …) |
| `blender_build` | Запускает `def build(mg): …` в живой сцене; возвращает висящие детали по строкам кода, треугольники по строкам, размер, асимметрию |
| `blender_view` | Отрендеренный лист из четырёх видов и до двух крупных планов, картинкой |
| `blender_measure` | Зазор между двумя частями: `"line 9"` и `"line 11"` кода сборки или имена объектов |
| `blender_facts`, `blender_scene` | Факты ещё раз; объекты с размерами, треугольниками и материалами |
| `blender_export` | Проверенный GLB + FBX по контракту MeshGate |

Если Blender открыт, включите связь в Sidebar (N) → MeshGate → Kit → **Connect AI**: сборки появятся в отдельной сцене
«MeshGate live» рядом с вашей. Без открытого Blender сервер запустит фоновый. Выполняется только код kit с теми же
ограничениями, что у `gen`: без прямого `bpy`, файлов и сети. Связь слушает только 127.0.0.1, случайный порт и токен
лежат в `~/.meshgate/blender_link.json`.

## Набор для моделирования на одном примере

```python
import math

def build(mg):
    mg.color("wood", "#8a5a2b", rough=0.8)
    mg.color("iron", (0.25, 0.25, 0.27), rough=0.5, metal=1.0)
    w, d, h = 0.8, 0.5, 0.35
    body = mg.join("chest_base", [mg.part("cube", "wood", loc=(0, 0, h / 2), scale=(w, d, h), bevel=0.01)]
                   + [mg.part("cube", "iron", loc=(x, 0, h / 2), scale=(0.05, d + 0.01, h + 0.01)) for x in (-0.3, 0.3)])
    lid = mg.join("chest_lid", [mg.part("cyl", "wood", loc=(0, 0, h), scale=(d, d, w), rot=(0, math.pi / 2, 0))])
    mg.pivot(lid, (0, d / 2, h))          # шарнир на заднем ребре
    mg.attach(lid, body)
    mg.animate(lid, "open", [(1, (0, 0, 0)), (20, (-1.9, 0, 0)), (40, (-1.9, 0, 0)), (60, (0, 0, 0))])
```

Полные примеры лежат в [`sources/generate/examples`](../sources/generate/examples).

## Что проверено

- **Сгенерированные ассеты в движках.** [Пак «Сгенерированное»](../samples/packs/generated/README.ru.md) — шесть
  ассетов из обоих движков, его пересобирает `meshgate.py samples`. Веб-вьюер показывает пак. Unity и Godot загружают
  каждый канонический файл и каждый файл уровня в пределах бюджета, а выбор файлов импортёром Unreal проверяется для
  каждого уровня.
- **Ход, отмена, вход.** Ход работы Blender приходит в CLI и Studio построчно, по мере готовности уровней. Отмена
  останавливает весь запуск, включая Blender и TripoSR; `check blender` проверяет это задачей, которая никогда не
  заканчивается. ИИ-CLI без входа останавливает генерацию сразу, `meshgate.py doctor` это показывает.
- **TripoSR вживую на M4 Pro.** Проверены установка, первый запуск и все последующие. Модель работает около 8 секунд на
  Apple GPU, доводка четырёх уровней занимает 15–40 секунд в Blender 3.5, 4.2 и 5.2; запекание идёт на процессоре, для таких размеров это быстрее видеокарты (`--gpu` переключает). Картинка гидранта превратилась в
  модель на 4–62 тысячи треугольников с патрубками и болтами фланца. Модель встала ровно после поправки наклона камеры
  на 20–25°. Если TripoSR установлен, `meshgate.py check blender` прогоняет это при каждой проверке.
- **Доводка без модели.** `check blender` и CI на каждой версии Blender пропускают через движок mesh плотную
  наклонённую сетку с цветом вершин. Она должна выйти ровной, без крошек, высотой 1,2 м и в бюджете каждого уровня.
  Цвет должен запечься, это проверяет декодер PNG.
- **Картинка → код набора.** Модель ИИ получила только промпт и картинку токсичной банки из пака котов-зомби. С первой
  попытки она написала код, повторяющий этикетку, жижу, лужи и открытую крышку, от 1,5 до 24 тысяч треугольников.
- **Текст → код набора.** Два прогона модели только по промпту дали уличный фонарь и мельницу с вращающимися крыльями,
  оба собрались с первой попытки. Подставной ИИ-CLI гоняет цикл исправлений на каждой версии Blender в `check blender`.
- **Облачные генераторы.** Meshy, Tripo, fal и картинки OpenAI проверяются на локальном подставном сервере по их
  документированным API. Тест проверяет форму запросов, заголовки авторизации, опрос и скачивание. Живые сервисы он не
  проверяет, им нужны платные ключи. Адаптер Tripo написан по частично опубликованному API v2.
- **Ограждения и промпт.** `tests/generate/test_generate.py` проверяет ограждения на 18 попытках обхода, промпт,
  передачу картинки каждому CLI, разбор ответа и имена, в CI и в `check web`.

## Ограничения и дальше

- Одна картинка показывает одну сторону, поэтому генератор додумывает зад. Тонкие детали и то, что лежит на полу,
  вроде луж, выходят каплями. Лучше всего работают фото настоящих цельных предметов на ровном фоне.
- Движок mesh запекает цвет и нормали; шероховатость — постоянные 0,7, карты металличности пока нет. PBR-карты облачных
  генераторов при запекании пока теряются.
- Персонажи с ригом по тексту или картинке, ввод с нескольких ракурсов и перенос PBR-карт — следующие в
  [роадмапе](roadmap.ru.md).
