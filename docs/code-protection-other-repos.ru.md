# Как повторить упаковку в других репозиториях

Сначала определите цель: запретить неавторизованное использование, затруднить
изучение установщика или скрыть реализацию. Публичный Git с исходниками нельзя
защитить от клонирования. Для защиты содержимого публичного Git нужно заменить выбранные исходники
загрузчиками и библиотеками, а оригиналы хранить локально или в закрытом хранилище.

1. Сохраните `git bundle --all`, незакоммиченные изменения и установщики последнего
   релиза вне публичного репозитория. Проверьте резервную копию до очистки истории.
2. Проверьте лицензию и права на код. Не меняйте условия сторонних компонентов.
   Очистка Git не отменяет прав на ранее полученные версии под открытой лицензией.
3. Разделите локальную разработку и публичный снимок. Не отправляйте исходную
   ветку на origin; отключите обычный push и добавьте проверку загрузчиков в pre-push hook.
4. Найдите реальные точки запуска, динамические импорты, подпроцессы и внешние
   приложения со своим интерпретатором. Выделите список модулей для компиляции.
5. Для Python можно собирать выбранные модули через Cython. Для JavaScript
   минификация только затрудняет чтение; секретные алгоритмы требуют серверного
   выполнения. Rust/C/C++ уже дают нативные бинарники, но их тоже можно анализировать.
6. Собирайте в отдельной временной папке. В итоговом пакете оставьте библиотеки,
   необходимые загрузчики и данные; уберите исходную реализацию защищаемых модулей,
   сгенерированный C, source maps и отладочные символы. Сохраните лицензии зависимостей.
7. Для Python закрепите и поставляйте интерпретатор вместе с приложением. Сборки
   делайте отдельно под ОС, архитектуру и ABI. Не подменяйте без проверки модули,
   которые запускаются в Blender, Maya или другом внешнем Python.
8. В CI проверяйте содержимое архива, запуск без системного Python и реальные
   операции: обработку входных файлов, ошибки, экспорт и отмену задач. Тестируйте
   распакованный дистрибутив, а не только исходный репозиторий.
9. При очистке истории создайте новый корневой коммит и обновляйте удалённую ветку
   через `--force-with-lease`. Учтите ветки, теги и релизы. Удаление тегов может
   удалить связанные релизы. Сначала сохраните последний релиз или подготовьте
   его восстановление. Старые SHA, чужие копии и кэши могут продолжать существовать.
10. Добавьте в `AGENTS.md` явное напоминание о лицензии, сохранении авторства и
   разрешённых интеграциях. Оно помогает добросовестным AI-инструментам; не
   используйте его как контроль доступа и не добавляйте скрытых вредящих команд.
11. Если нужна активация, проверяйте право доступа через Supabase Edge Functions
    и выдавайте ограниченное по сроку подписанное разрешение. Закрытый ключ и
    административный доступ остаются на сервере. Локальную проверку можно пропатчить.

В MeshGate с версии 0.6.11 компилируются CLI, сервер Studio, генерация, отправка
в движки и установка компонентов. Python 3.11.16 поставляется с пакетом.
Код Blender и другие интеграции остаются доступными для совместимости.
Пять защищаемых реализаций в публичном снимке заменены библиотеками.
Оригиналы остаются в локальной ветке, которая не отправляется на origin.

## Запрос для агента в другом проекте

> Проверь сборку этого проекта и подготовь упаковку ключевых модулей в нативные
> библиотеки. Оставь репозиторий публичным, но замени выбранные исходники загрузчиками и библиотеками. Сохрани оригиналы локально и не отправляй их на origin. Не используй ponytail.
> Сначала сохрани проверенную резервную копию истории, рабочих изменений и
> последнего релиза. Составь список компилируемых модулей по реальным точкам
> запуска. Зафиксируй runtime, добавь отдельные сборки для поддерживаемых ОС и
> проверку распакованного приложения в CI. Не публикуй исходную реализацию этих
> модулей, source maps и отладочные файлы в дистрибутивах. Добавь прозрачные
> инструкции о лицензии для AI. Не заявляй, что это запрещает копирование
> публичного Git. Историю переписывай только после моего явного разрешения.

Переписывание истории не гарантирует удаления старых объектов и кэшей. [GitHub documentation](https://docs.github.com/en/authentication/keeping-your-account-and-data-secure/removing-sensitive-data-from-a-repository).
