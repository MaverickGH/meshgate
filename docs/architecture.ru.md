# Архитектура MeshGate — «ступица и спицы»

```
  Blender ─┐                              ┌─→ Web (Three.js)
  Maya ────┤→  нормализованный GLB  ──────┤─→ Unity (glTFast)
  (…)      │   (контракт ассета)          ├─→ Godot (native)
           │   + валидатор                └─→ Unreal (native/Interchange)
  источники                                  цели
```

**Ядро** — канонический glTF 2.0 (GLB) по контракту ассета + валидатор. Ядро не
знает ни про конкретный редактор, ни про конкретный движок.

**Источники (spokes-in)** приводят ассет к каноническому GLB:
- Blender — родной экспорт glTF с пресетами контракта.
- Maya — glTF нет из коробки: путь через плагин (Maya2glTF/Babylon) либо через FBX/USD → конвертация в GLB.

**Цели (spokes-out)** принимают канонический GLB:
- Web — Three.js `GLTFLoader`.
- Unity — glTFast (MIT).
- Godot — родной импорт glTF (предпочтительный формат движка).
- Unreal — родной glTF-импортёр / Interchange.

## Запасной путь: FBX / USD
Веб живёт на glTF, но для Maya-происхождения и тяжёлых риг/больших сцен в движках
иногда нужен нативный формат:
- **FBX** — де-факто стандарт DCC↔движок (родной в Maya, есть в Blender, импорт во всех движках; Godot конвертит в glTF).
- **USD** — студийный обменник сцен (родной в Maya и Unreal, развивается в Blender/Unity).
MeshGate оставляет FBX/USD «насквозь» для таких кейсов, но канон для веба+реалтайма — glTF.

## Добавление нового источника/цели
Новый редактор = адаптер в `sources/`, который выдаёт GLB по контракту.
Новый движок = адаптер в `targets/` c импортом канонического GLB и обвязкой интерактива.
Ядро и контракт при этом не меняются.
