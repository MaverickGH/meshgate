# MeshGate Studio

Приложение для macOS и Windows, которое превращает описание или картинку в готовый для игры ассет. Пишешь, что
нужно, или перетаскиваешь картинку, выбираешь стиль и уровни качества, жмёшь **«Сгенерировать»**. Studio либо просит
твой ИИ-инструмент командной строки написать код набора, либо запускает нейросеть, которая делает сетку. Потом строит
модель в Blender отдельно под каждый уровень, проверяет её по контракту ассета и показывает результат в 3D-вьюере, по
вкладке на уровень.

![MeshGate Studio](../../docs/img/studio.png)

Это окно вокруг [`meshgate.py gen`](../../docs/generation.ru.md). Всё, что оно делает, — обычные файлы, которые можно
нести в web, Unity, Godot или Unreal.

## Что нужно

- **Blender 3.5 или новее.** Studio находит его в обычных местах, иначе задай `MESHGATE_BLENDER`.
- **Python 3.9 или новее на macOS/Linux и для обычного переносного архива.** Windows x64 установщик и Windows-архив включают собственные Python и uv. `MESHGATE_PYTHON` позволяет использовать другой Python.
- **Один ИИ-инструмент командной строки, с одним входом:** Claude Code (`claude`, затем `/login`), Codex CLI
  (`codex login`), Gemini CLI (`gemini`) или Ollama для работы без интернета. Любой другой CLI подключается через
  **«Нейросеть и дополнительно» → «Своя команда»**.
- **Для картинок — генератор сеток:** нажми **«Установить TripoSR»** в разделе «Нейросеть и дополнительно». Он работает
  локально, под лицензией MIT и занимает около 3 ГБ. Или задай `MESHY_API_KEY`, `TRIPO_API_KEY` или `FAL_KEY` перед
  запуском Studio.

В шапке видно, что Studio нашла: зелёная точка у Blender и у каждого ИИ-CLI из твоего PATH. **«Статус и ИИ»**
открывает одно окно для всего этого: Blender, Unity, Godot и Unreal с версиями, аддон Blender с кнопкой **«Поставить
аддон»**, плагин MeshGate для каждого движка с кнопкой **«Файлы плагина»** (папка, которую копируешь в проект), у
каждого ИИ-инструмента кнопки **«Установить»** (в окне терминала) и
**«Войти»**, установка TripoSR и поля для облачных ключей. Ключи сохраняются в `~/.meshgate/keys.json`, файл читаешь
только ты, а показываются только последние четыре символа.

## Установка

- **Из релиза:** скачай `MeshGate Studio_<версия>_aarch64.dmg` (macOS) или `.msi` / `-setup.exe` (Windows) со страницы
  [Releases](https://github.com/MaverickGH/meshgate/releases). Сборки пока не подписаны. На macOS в первый раз нажми на приложение правой кнопкой и выбери
  **«Открыть»**. На Windows в SmartScreen выбери **«Подробнее» → «Выполнить в любом случае»**.
- **Linux или без установки:** скачай `MeshGate-<версия>-portable.zip` из того же релиза, распакуй и запусти
  `python3 meshgate.py studio`. Откроется тот же интерфейс в браузере на любой ОС; нужны только Python 3.9+ и Blender.
  Из клона репозитория работает та же команда.

Сгенерированные ассеты сохраняются в `~/Documents/MeshGate Assets`, а при запуске `meshgate.py studio` внутри
репозитория — в `out/gen`. У каждого ассета своя папка, кнопка **«Показать файлы»** её открывает.

## Как пользоваться

1. Опиши модель на любом языке, перетащи картинку или сделай и то и другое. Подсказки под полем — примеры.
2. Отметь **«Сначала нарисовать концепт»**, чтобы Codex, OpenAI или fal нарисовали предмет до сборки: лист видов
   спереди/сбоку/сзади/сверху для кода набора, один ракурс 3/4 для нейросетки. Затем выбери, **как строить**. **«Код набора»**: ИИ пишет чистый редактируемый код, лучше всего для стилизованных
   предметов; картинку он использует как образец. **«Нейросетка»**: TripoSR или облачный генератор, лучше всего для фото
   настоящих предметов. **«Авто»** выбирает нейросетку, если есть картинка и готов генератор.
3. Выбери стиль (стилизация, low-poly, реализм или мульт) и цвета: **«Текстуры»** или **«В вершинах»** (совсем без
   текстур). По желанию задай имя и размер в метрах.
4. Отметь нужные уровни качества; самый богатый станет каноническим `<имя>.glb`. Число рядом с уровнем — твой лимит
   треугольников для него, когда треугольников нужно намного меньше. Отметь движки, для которых нужны
   варианты.
5. Нажми **«Сгенерировать»**. **«Ход работы»** показывает каждую попытку: что ответил ИИ, как вышел каждый уровень и
   какие проблемы ушли ИИ на исправление. **«Код»** показывает итоговую функцию `build(mg)`.
6. Переключай уровни под вьюером, чтобы увидеть, что получат телефоны и что получит PC. **«Библиотека»** хранит все
   сделанные модели.

### Доработка модели

Вкладка **Доработка** ведёт модель kit дальше, как художник:

- **Изменить словами** — «уши побольше, шерсть на груди длиннее»: ИИ получает код и модель с четырёх сторон (рядом с
  картинкой) и меняет только это.
- **Параметры** — ползунки, которые код объявил через `mg.param` (размер ушей, длина шерсти, вытянутость рук…);
  **Пересобрать** собирает заново без ИИ, у стилизованных моделей за секунды.
- **Версии** — каждое изменение сохраняет прошлое состояние (код, ползунки, превью); **Вернуть** возвращает его.

### Своя модель, части и отправка в движок

- **Своя модель.** Перетащи GLB, FBX, OBJ, PLY или STL туда же, куда картинку, и нажми **«Сгенерировать»**: модель
  ляжет в библиотеку — почищенная, с новой топологией и запечённая под каждый уровень, проверенная как сгенерированная.
- **Части.** Отметь **«Разделить на части»** (настройки вывода) перед генерацией или нажми **«Разделить эту модель на
  части»** на вкладке **«Части»**: каждая отдельная вещь станет своим объектом — из кучи ящиков получится объект на
  каждый ящик, с именем по цвету (цвет палитры у моделей kit, запечённый в текстуру цвет — у твоих) и точкой опоры внизу;
  номера идут по месту — нижний ряд первым, слева направо, — так что у части одно имя на всех уровнях. На вкладке
  **«Части»** нажми на кусок в окне или в списке и тяни за ручки (**«Двигать»**, **«Повернуть»** вокруг вертикали,
  **«Масштаб»**), выбери другой **«Цвет»** (палитра модели kit; у запечённой модели перекрашивается текстура под частью,
  свет и детали остаются), **«Дублировать»** или **«Удалить»**. Клавиши: W / E / R, ⌘/Ctrl+D, Delete, ⌘/Ctrl+Z —
  отменить. **«Сохранить и пересобрать»** соберёт все уровни с правками. Они хранятся в `edits.json` рядом с моделью и
  повторяются при каждой пересборке; **«Вернуть как было»** их снимает.
- **Панель под моделью** работает с моделью в окне: **«Текстура»** (размер, текстуры или цвета в вершинах, полный
  PBR), **«Ремеш»** (один целевой полигонаж — «Обычный», 3K, 10K, 30K, 100K — и квады или треугольники),
  **«Развернуть UV»** (UV-сетка на модели или развернуть и запечь заново), **«Части»**, вилка — отправить в движок, и
  **«Скачать»** (каждый GLB, FBX и .blend). Каждое изменение пересобирает все уровни и сохраняет прошлое состояние как
  версию. Пояснения к настройкам спрятаны в ⓘ рядом с их названиями.
- **«Внешность»** — редактор персонажа: каждый ползунок `mg.morph` модели (размер головы, уши, глаза, живот, длина
  ног…) и каждый цвет палитры меняют модель в окне сразу, как в игре; **«Случайно»** выдаёт новый вид, **«Как было»**
  возвращает. **«Сохранить внешность»** пересоберёт все уровни с ней (`look.json` рядом с моделью); ползунки остаются в
  GLB и FBX морфами, так что их может двигать и твоя игра.
- **«Отправить в…»** Unity, Godot, Unreal или Blender (вилка на панели): файлы лягут в твой проект —
  `Assets/MeshGate/<модель>/` (GLB каждого уровня и FBX), `res://meshgate/<модель>/` или `Content/MeshGate/<модель>/`
  (FBX) — и в следующий раз заменятся на месте, так что движок их переимпортирует. Blender откроет `.blend` модели.
  Папку проекта спросят один раз и запомнят (`~/.meshgate/bridge.json`). Из командной строки:
  `python3 meshgate.py send <папка модели> --to unity --project <папка>`.

Полоса прогресса под кнопкой «Сгенерировать» показывает этап, проценты и примерное время до конца — оно учится на
твоих прошлых запусках. Клипы персонажа (idle, walk, attack) проигрываются кнопками рядом с «Сетка».

## Как устроено

| Часть | Что делает |
|---|---|
| [`server.py`](server.py) | Локальный сервер на 127.0.0.1: интерфейс, JSON API, задачи с `meshgate.py gen --events`; только stdlib |
| [`ui/`](ui) | Страница: форма, ход работы, библиотека и веб-вьюер MeshGate для 3D |
| [`desktop/`](desktop) | Оболочка на Tauri 2 (Rust, около 6 МБ): запускает сервер и открывает его страницу в родном окне |

**Безопасность.** Сервер слушает только локальный адрес. Каждый запрос к API требует токен сессии, а заголовок Host
должен быть локальным адресом, поэтому веб-страницы и другие машины не могут управлять твоим ИИ-CLI или Blender.
Десктоп-оболочка передаёт токен через переменную окружения, поэтому он не виден в списке процессов. Сгенерированный
код перед запуском проходит [ограждения](../../docs/generation.ru.md#движок-kit-код-пишет-ии).

**Вьюер без интернета.** `scripts/vendor_three.py` копирует модули three.js, которые использует вьюер, в `ui/vendor`;
сборка приложения запускает его сама. Без копии сервер перенаправляет эти запросы на CDN.

**Логи.** Десктоп-приложение пишет вывод сервера в `~/Library/Logs/dev.meshgate.studio/studio.log` на macOS и в
`%LOCALAPPDATA%\dev.meshgate.studio\logs\studio.log` на Windows.

## Сборка приложения

```bash
cd apps/studio/desktop
npm ci
npx tauri build --bundles app,dmg      # macOS; на Windows: npx tauri build --bundles nsis,msi
```

Нужны Node 20+ и Rust. Первая сборка занимает несколько минут. Workflow
[`studio-desktop`](../../.github/workflows/studio.yml) собирает установщики для macOS и Windows по тегу версии или по
запросу. `npx tauri dev` запускает оболочку прямо на репозитории, без упаковки.

## Что проверено

- `tests/studio/test_server.py` проверяет маршруты, токен, заголовок Host, выход за пределы папки и маршрут three.js.
  Тест идёт в CI и в `meshgate.py check web`.
- Полная генерация из интерфейса с подставным ИИ-CLI: первый ответ падает, исправление собирается, библиотека
  обновляется, вьюер загружает новую модель.
- Приложение для macOS собрано и запущено так, как его запускает Finder. Оно нашло Blender и Claude Code через PATH
  оболочки входа, загрузило интерфейс в окне и ответило на запросы к API.
- `tests/studio/test_bundle.py` запускает собственную копию MeshGate из приложения: файлы на месте, сервер из
  комплекта отвечает, three.js отдаётся без интернета, сборка кодом набора и доводка сетки работают из комплекта. CI
  запускает его после каждой сборки установщика.
- `tests/studio/test_cancel.py` отменяет задачу, чья сборка никогда не кончается, и проверяет, что её Blender исчез.
  При выходе из приложения сервер сначала отменяет задачи, поэтому Blender не остаётся работать.
- Ход работы приходит построчно, пока Blender работает, а не только в конце.
- На Windows собраны установщики NSIS и MSI, выполнена установка NSIS и проверен запуск сервера десктоп-приложения.
  Установленный комплект прошёл проверки файлов, API, офлайн-вьюера, сборки kit и обработки сетки с Blender 4.5 LTS.
  Также проверен переносной Windows-лаунчер; аддон Blender прошёл 35 проверок.
- Windows x64 сборки включают собственные Python и uv. Переносной комплект прошёл запуск сервера, сборку промпта, kit и mesh при чистом PATH без системного Python; TripoSR установлен без Git и использует независимый управляемый Python для моделей.
